The Aether host builds the existing NitroSharp engine as an in-process NativeAOT shared library. Its C contract is in `include/aether_n2system.h`. A host owns the event loop and receives borrowed, top-down RGBA8 frames; the engine uses an offscreen Metal, D3D11 or Vulkan framebuffer and creates no SDL window. Calls for each instance must run serially on its creating thread. Distinct instances may use separate threads. `destroy` releases the instance and another game can then be opened in the same process.

Build with `./aether_runtime/build_host.sh` or `dotnet publish aether_runtime/AetherN2System.Host.csproj -c Release -r osx-arm64 -p:NativeRid=osx-arm64 -o OUTPUT`, replacing the RID with the native desktop platform. A .NET 10 or newer SDK with NativeAOT support and the platform C toolchain are required. Desktop NativeAOT publishing requires a matching host OS. The Aether mobile build scripts also support Android ARM64 with the Android NDK and iOS with Xcode. Android packages the host and its native dependencies as JNI libraries and embeds fonts in the host image. iOS links a static host with its NativeAOT runtime and initialization object into the application; its dependencies use direct P/Invoke and graphics use Metal. Android startup, rendering, input and destruction have been verified on a device; iOS verification currently covers compilation and linking only. Generated shader resources are checked in; regenerating them after shader changes requires `glslangValidator`, `spirv-cross`, and `python3 aether_runtime/compile_shaders.py`.

ImageSharp uses the assembly-scoped Six Labors Community license in `src/NitroSharp.Rebuild/sixlabors.lic`, which is included for local and CI builds. Renew it before expiry using the same licensed assembly names. If you rename an assembly that uses ImageSharp, obtain a license covering the new name.

Deploy the complete publish output, including Fonts, beside the provider's N2 host library. FreeType must be provided for the target architecture with its dependent libraries. Aether's main CMake build supplies this dependency from vcpkg. The optional `stage_macos.py OUTPUT` script stages local Homebrew libraries for development tests; its output is not a release package and can require a newer macOS than Aether's deployment target. Native dependencies and Fonts are resolved relative to the shared library itself, independently of the process working directory. OpenAL output is implemented; macOS can use the system OpenAL framework. Media decoding uses the FFmpeg 4 library ABI and requires matching native libraries. Movies support frame uploads, playback completion, pause/resume, looping and script-controlled skipping.

Place an `aether-n2system.json` or `profiles.json` in the game directory using NitroSharp's existing profile format. Relative `dev.contentRoot` values resolve from that directory. A profile may omit optional display, icon and font settings. Without one, the host tries `nss/boot.nss` at 1280×720. `nss.npa` scripts are extracted into the supplied writable directory using the configured archive encoding and NPA scheme, with path traversal and extraction-size checks; other NPA files are mounted under their file stem. Unsupported archive schemes return an explicit error. The game directory and process working directory are not modified. This bridge does not establish compatibility with any commercial title.

Early N2System installations with PAK v3 archives and `game.ini` / `sys.ini` configuration use the legacy NPS adapter. It prefers localized `_cn.ini` files and loose patch resources, translates reachable scripts into the writable cache, and mounts PAK entries at their authored paths. The adapter handles image and text choices, configured horizontal and vertical textboxes, backgrounds, actor layers, shared GLASS/ANIM slots, audio, movies, jumps and dialogue. Frame animations preserve missing-frame holds, final-frame selection, input interruption and retained stills across scene wipes. Legacy wipes composite the whole incoming scene with cumulative palette-index mask weights; DELAYFADE retains a changing scene as queued fixed-point scrolls advance. Synchronous scrolls, whole-scene quake and horizontal image credit rolls are also supported. Unsupported operations stop execution with the original script name, line and command. Legacy SAVE/LOAD commands open a host menu with touch and keyboard controls, timestamps and overwrite confirmation. SYSTEM MENU save/load restrictions are honored. Automatic legacy choice saves and some playtime requests remain unsupported and report the missing capability explicitly. When a translation changes actor names, the adapter can recover an image alias from matching original and translated voice resources only when the speaker mapping is consistent and the exact target image exists. Missing optional choice sounds are reported without preventing selection.

For translation patches that mix encodings, `dev.scriptEncoding` selects the structural encoding and optional `dev.dialogueEncoding` selects the encoding of PRE dialogue, Ruby text and SetFont family names. `dev.dialogueVariables` is a comma-separated list of display variables whose directly assigned quoted strings use the dialogue encoding. Paths, identifiers, voice metadata and embedded script retain the structural encoding. UTF-8 and BOM-marked sources use their own encoding. Known localized Muramasa layouts supply these defaults automatically, while explicit profile settings take precedence. Legacy Twitter calls report unavailable or canceled results locally so scripts can follow their offline branches.

Dialogue renders per-character fades and honors script-controlled input, text hiding and vertical glyph orientation. Opening the authored system menu suspends the story process and returning preserves its current page. `WaitAction` waits for the captured entities' animations, child threads and finite media; `Reset` replaces the active scene and threads at an update boundary while preserving VM globals. Persistent slots serialize the main story process, VM call/evaluation stacks, variables and array aliases, entity hierarchy, dialogue progress, visual animations, snapshot textures and media playback state. Slot 0 persists shared flags/settings; ordinary slots preserve the latest shared settings when loaded. Saves use `savedata/AetherN2System/<game-profile-id>/` inside the game directory, falling back to the host writable savedata root only when the game directory cannot be written. Existing app-private saves migrate once without overwriting game-local files; deleting migrated game-local saves does not import the old copies again. The VM save path, slot existence checks, checkpoint reads/writes, thumbnails and authored sidecars all use the same selected directory. The engine writes thumbnails and the original scripts can read/write their date, comment, chapter and playtime sidecars. F5/F9 save/load quick slot 9998; a missing authored system menu falls back to the host save menu. Checkpoints use a versioned, checksummed Aether format and reject changed scripts. They do not import Windows-original saves. Saving during an active legacy scene wipe reports an error; wait until the wipe completes.

`CreateEffect` supports `Plain` as a design-coordinate crop of the last completed presented frame. `Request(..., Passive)` freezes an owned snapshot that remains visible after its source entities are deleted and can still move, fade, and lock. Active Plain effects refresh from the previous presented frame, so they do not reproduce the original engine's same-frame effect composition. `SetShade` preserves native strengths from LIGHT through NOMORE; an explicit null restores the original image and NORMAL preserves the current state. Other effect names retain explicit unsupported diagnostics.

`python3 aether_runtime/smoke.py OUTPUT/aether_n2system.dylib` exercises the real native ABI using `manual_tests`, an input-driven color fixture, a generated plain NPA, repeated destruction and reopening, pause/resume, and compressed-archive diagnostics. The text, typewriter, vertical text, screen capture, blur, frame sequence, mask transition and legacy transition helpers exercise their respective rendering contracts through the same ABI. `python3 aether_runtime/video_smoke.py OUTPUT` generates movies and checks their playback lifecycle; it requires `ffmpeg`. `dotnet run --project aether_runtime/tests/AudioSmoke.csproj -c Release -- /absolute/path/to/libopenal.dylib` feeds generated PCM to the real OpenAL device and checks playback position and pause/resume. Passing the FreeType library path and a font path as two additional arguments also rasterizes a real glyph. The standalone `src/Game` entry point is preserved. The NativeAOT library stays loaded for the process lifetime; only game instances are destroyed.
